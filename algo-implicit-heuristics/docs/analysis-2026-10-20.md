## 一、语言"AI 味"诊断

### 1.1 先说结论

课题文的 AI 味不是"遣词造句"层面的，而是**制度性产生的**：SKILL.md 5.1 的句式禁令 + 五段式固定模板 + 核心动词强制复现三项机制叠加，把所有能承载"人味"的载体系统性地清空了。剩下的只有一种可写出的文体——**第三人称的教材旁白**。

三篇课文（含两份 fixture）实测：

| 课文 | 汉字 | 句数 | 第二人称"你" | 口语标记 | 问句 | 破折号 | 抽象名词句 |
|---|---|---|---|---|---|---|---|
| `tests/fixtures/cycles_lesson.txt` | 352 | 17 | **0** | **0** | **0** | 2 | 1 |
| `tests/fixtures/good_lesson.txt` | 294 | 17 | **0** | **0** | **0** | 2 | 0 |
| `lessons/3886-sum-of-sortable-integers.lesson.txt` | 700 | 26 | **0** | **0** | **0** | 3 | 2 |

合计：**0 个"你"、0 个口语标记、0 个问句**。这不是文风偏好问题——真人在课堂上讲一道题，不可能 17 句话里不出现一次"你"。

### 1.2 逐份文件的具体问题

#### （1）`examples/01-cycles.md`（及 `tests/fixtures/cycles_lesson.txt`）

**A. 抽象名词三连的"总结收尾"** —— `examples/01-cycles.md:17` / `cycles_lesson.txt:9`：

> 这个数组的元素分布构成一个长度为 3 的环，交换的最小次数由环的结构决定，状态映射的闭合形状给出了操作次数的下界。

"元素分布构成…环" / "由环的结构决定" / "状态映射的闭合形状给出了…下界"——三个抽象名词短语连排做定语，是 LLM 最典型的收束句式。真人会写"所以这题就是数一圈有几个圈"。

**B. 机械排比** —— `cycles_lesson.txt:3`：

> 同一组数，同一个目标，两种操作规则给出的次数是 1 和 3。

"同一…同一…两种…是 X 和 Y"的四字对仗。真人会说"同一批数字，换个规矩，答案就从 1 变成 3"。

**C. 破折号承担"解释转折"** —— `cycles_lesson.txt:5`：

> 沿着"该去哪"一路走下去，最后走回出发点——这样的闭合行程就是环。

以及 `cycles_lesson.txt:7`："…这句话开始动摇——下标 0 的 2 和下标 1 的 2…"。两处破折号后面接的都是"补充解释从句"，形成**可预测的节奏：事实—破折号—解释**。中文口语几乎不用破折号。

**D. 零第二人称** —— 全文 17 句没有一句对读者说话。`cycles_lesson.txt:1` "把它送过去，2 被换到下标 0" 是标准解说词旁白。真人讲到这里会是"你把 3 送过去试试，注意 2 被挤到 0 位置了"。

#### （2）`examples/02-adjacency-xor.md`（及 `tests/fixtures/good_lesson.txt`）

**A. 分号排比 + 破折号"翻译成大白话"** —— `good_lesson.txt:5`：

> 段内两两相等，留下一个，删掉 k−1 个（k 是段长）；两段的交界处，值必然不同，不用处理。

`good_lesson.txt:9`：

> 连续段把相等的元素聚成块，答案就是每块长度减一之和——也就是数一数有多少对相邻元素相等。

前半句论文腔、破折号后"也就是…"翻译成大白话——这种"高配版 + 降配版"的双层结构，正是 LLM 输出的典型指纹。

**B. 术语先行** —— `good_lesson.txt:5` 的"翻译过来，条件里只剩相等和相邻两件事"：这是把"翻译"这个核心动词直接用成了**题解术语**，而不是让动词自然渗透。动词一旦变成术语，渗透就变成了宣告。

#### （3）`lessons/3886-sum-of-sortable-integers.md`（今天新增这篇也在内）

**A. 连接词是 LLM 标志物** —— `.lesson.txt` 第 3 段：

> 判据于是缩成一句：每块自己成一个圈，绕一圈只断一次，断口对上的正是它该对齐的那一块。

"于是缩成一句"是高频连接词。同段还有"整串非递减这句话把目标钉死了"。

**B. 任务指令的模板腔** —— 末句：

> 换成 [3, 4, 1, 2] 这串长度 4 的数组，同样把能算数的 k 列出来。

"同样把…列出来"是命题腔。真人会说"要不你拿这个练手？答案先别看"。

**C. 破折号密度最高（3 处/700 字）** —— "这就是它们该对齐的那一串——不是随便哪种排好的样子，而是这四个数排好序之后必然长成的那一个。"：破折号后接"不是 X，而是 Y"的对举，是 LLM 最爱用的解释句式之一。

#### （4）元文档（`SKILL.md` / `docs/design.md` / `docs/roadmap.md` / `README.md` / `HANDOFF.md`）

元文档的 AI 味明显轻于课文——它们是工程文档而非讲解，读者预期是"规范"。但仍有两处会外溢到课文生产：

- `docs/design.md:30`："清单能查句式、位置、数量，查不出'这段讲解有没有真的让人产生疑问'。" —— 完整、正确、但像论文摘要。
- `SKILL.md` 的第 4 章把"第一段 / 第二段 / 第三段 / 第四段 / 第五段"写死为**固定槽位**，于是三篇课文的第一句全部是"数组 […]。"或"nums = […]。"，第五句全部是"回到最初那个数组 […]：" / "回到 [1, 1, 2]：" / "回到 [2, 1, 4, 3] 这串："。**模板同构 → 读者读第二篇时已经在填空。**

### 1.3 哪些"设置"会加剧这种倾向（机制级）

这是本节最关键的部分。**AI 味不是执行者的锅，是清单的锅。**

| 设置 | 位置 | 副作用 |
|---|---|---|
| 句式禁令把**所有面向读者的第二人称互动**清空 | `SKILL.md:160-166` 第 1/3/4 项（`你理解｜你觉得｜你确定｜你熟悉｜懂了吗｜试试看你能｜检查一下你`） | 直接封死了"你试一下""你卡在哪儿""咱们看这个"——真人课堂里人味的主要载体 |
| 核心动词**强制复现**（≥2 次且跨 ≥2 段） | `SKILL.md:192` 第 8 项 | 文本出现"刻意重复"的机器感；真人不会每段都甩同一个词 |
| 禁止定义句式 `所谓｜是指｜的定义是` | `SKILL.md:166` 第 6 项 | 连"X 就是……"这种最自然的定义都写不了，只能用"它有一个名字：环"这种文艺说法绕 |
| 回扣段**必须复现实体**（同一数组字面量再写一遍） | `SKILL.md:177` 第 9 项 | 文本里出现突兀的字面重复 |
| 五段式固定槽位 | `SKILL.md:131-143` 第 4 章 | 开头/结尾模板化，跨篇同构 |
| 成文模式一次性输出 | `SKILL.md:374-379` 7.9 | 没有接话余地，只能写成独白；一问一答的"人味"载体全部失效 |
| 全文以"读者"第三人称指代 | `SKILL.md:281-303` 层级 A/B/C 描述 | Agent 内部把"读者"当客体 → 输出也倾向把读者当客体 |
| 模块声明要求"核心动词比题解术语更根本" | `CONTRIBUTING.md:16` | 方向对，但一旦动词被选定为考核对象，它就会从"自然用词"退化成"必须出现的词" |

**机制链条**：`禁止第二人称` → `没有称呼` → `没有语气` → `只剩陈述` → `陈述只能是教材体` → **AI 味**。

### 1.4 可执行的方向（本轮不改，仅记录）

1. **给 5.1 加白名单而不是只加禁令**：允许"你"出现在**产出型任务**里（"你把这三个 k 判一下"、"你试试 k=2"），只禁**评价型**用法（"你懂了吗"）。判据沿用 SKILL.md 7.8 已有的一致性标准（对象是内容还是自我状态），不需要新造标准。
2. **把"禁止破折号"与"禁止"的清单分级**：5.1 第 1–4 项是句式类（0 命中），可加第 14 项"单篇破折号 ≤ 1"作为**软指标**，只提示不拦截。
3. **第 8 项从"词频考核"改成"读起来是否自然"**：硬性词频会逼出机械重复；可以保留术语清单，但动词考核改为人工标注（执行标注表里加一列"渗透位置"）。
4. **第 9 项允许变体复现**：不必逐字复现 `[2, 1, 4, 3]`，复现"同一组数据的同一串"即可。
5. **课文增加一段"人称锚点"**：模板的第 1 段可以加一句第二人称的临场动作（"先别看答案，你把 k=2 摆出来转转"），不影响任何机器检查。

## 二、运行速度慢的原因

### 2.1 实测基线（本机，Windows / Git Bash）

| 项目 | 实测值 |
|---|---|
| 裸 Python 解释器启动 | **0.748 s**（min 0.718） |
| `check_lesson.py` 完整跑一次 | **0.767 s**（min 0.761） |
| → 脚本自身净耗时 | **0.019 s**（占 2.5%） |
| `SKILL.md` | 47,348 B ≈ **15,800 tok** |
| 一次教学需读文件合计（SKILL + 脚本 + 2 篇示例 + design + roadmap + README + HANDOFF） | 78,068 B ≈ **26,000 tok** |
| 技能副本 | 项目级 `skills/` 与用户级 `~/.workbuddy/skills/` **逐字节相同**（`diff -rq` 无输出）→ 上下文里存在两份同样的 15.8k tok |

### 2.2 首次使用的一次性成本

| # | 成本项 | 量化 | 说明 |
|---|---|---|---|
| 1 | 技能正文进入上下文 | ~15.8k tok | SKILL.md 每次必读，无按需加载机制 |
| 2 | 路由所需的模块信息 | ~1.9k tok + 2 次文件读 | `docs/modules.md` 尚未创建（roadmap 1.1 待办），路由只能靠读 `examples/` 猜 |
| 3 | 上下文累积 | 最多 ~26k tok | design / roadmap / README / HANDOFF 常被一并读入 |
| 4 | 校验链路多一次写 + 一次读 | — | 仓库约定"示例课与 fixture 是两份文本"（HANDOFF §6），跑脚本前必须先落盘 `.txt` 副本 |
| 5 | 解释器冷启动 | 0.75 s × 首次 | 首次还有 `.pyc` 编译 |

### 2.3 稳定状态下的固有开销

| # | 开销 | 性质 | 量化 |
|---|---|---|---|
| 1 | 产出课文的模型调用 | **不可避免**（主体成本） | 一次生成 ~700–1500 字 + 判据 + 代码 |
| 2 | 5.1 要求"输出前全文执行一遍" | 固定 | ≥1 次脚本调用（0.77 s）+ **1 轮模型自查改写**（秒级~十秒级） |
| 3 | 第 7 项"并置案例单参数差异"人工核对 | 固定且**不可自动化** | 模型必须再通读全文一遍（完整额外注意力成本） |
| 4 | 成文模式天然一轮返工 | 结构性 | 先出课文 → 判信号 → 才决定降不降级（SKILL.md 7.9 判定延后） |
| 5 | 串行 barrier | 固定 | 写文件 → 跑脚本 → 读报告 → 改 → 再跑，每轮 = 0.77 s 进程启动 + 一次模型往返 |
| 6 | prefill 随上下文线性增长 | 固定 | 每轮模型调用都要重算 26k 常驻 + 课文 + 报告 |

**结论**：脚本本身不是瓶颈（净 0.019 s），**Windows 上的进程启动占 97.5%**；真正的固有成本是**第 2/3/4 项——"生成 + 自查 + 返工"的三遍文本处理**，而 token 侧的浪费主要来自 26k 常驻上下文与技能双副本。

### 2.4 可优化点（按性价比排序）

| # | 动作 | 收益 | 代价 / 风险 |
|---|---|---|---|
| 1 | 校验脚本改用 Node（`node` 冷启动 ~50 ms 量级）或把 Python 常驻 | 单次校验 0.77 s → ~0.1 s，N 轮线性受益 | 重写 110 行脚本 + 改 CI；`tests/test_check_lesson.py` 需同步 |
| 2 | 拆 `SKILL.md`：正文只留路由 + 五段式 + 5.1 清单，第 3/7 章下沉为 reference 按需读 | 常驻 15.8k → ~6–8k tok | SKILL.md 内部有 **92 处小节号引用 + 25 处"第 N 章"引用**（实测无悬空），拆分需逐一改写并加"悬空引用"自动检查（roadmap 2 已列 `check_skill.py`） |
| 3 | 只保留一份技能副本（建议留用户级安装版，仓库版只作 git 源） | 省 ~15.8k tok 重复占用 | 破坏 HANDOFF §2"仓库是唯一权威来源、部署时覆盖"的约定 → 需先改约定 |
| 4 | `check_lesson.py` 支持 `--from-markdown`，直接解析 `.md` 的课文段 | 去掉"两份文本"的一次写 + 一次读 | 需保留旧模式以兼容 HANDOFF §6 的 fixture 约定 |
| 5 | 把第 7 项做成结构化标注（案例块加 frontmatter 式的差异声明） | 省掉一次全文人工通读 | 需改课文格式，roadmap 2 已列 |
| 6 | 默认走交互模式，成文模式需显式请求 | 省成文模式的一轮返工 | 改变默认行为；与"一次给出完整篇"的期望冲突 |
| 7 | 新建 `docs/modules.md`（模块 → 表述模式 → 示例课的索引） | 省 ~1.9k tok + 1–2 次文件读，路由从"读示例猜"变成"查表" | roadmap 1.1 已有此待办，成本低收益高 |

## 三、重新设计讲解流程

### 3.1 现状的结构性问题

现有流程（SKILL.md 第 8 章八步）把"读者已经读懂了什么"当成**待推断的隐变量**，所以第一件事就是给案例（S0 直接进五段式），诊断信号只能从案例反应里捞。三个具体缺口：

1. **题面本身从未成为教学对象**。很多"卡住"其实发生在读题阶段（目标到底是什么），而现有流程默认读者已经读懂了题。
2. **读者脑中的错误模型没有出口**。诊断层三态表能判断"缺不缺前置"，但拿不到"你以为这题在干嘛"——而后者恰恰是最值钱的教学素材。
3. **"第一感觉"被当成噪音丢弃**。初学者的直觉经常含有正确的部分（如"每块自己排好序"这个错误直觉里，"块内有序"是对的、只是"跨块也要有序"漏了），把它摆上台面，后面才能精准地打掉它，而不是含糊地说"这题不简单"。

### 3.2 新流程：七阶段

起点 = **复述题目**，推进器 = **第一感觉**，终点 = **复盘**。

| 阶段 | 意图 | 输出形式 | 用户交互点 | 采集信号 |
|---|---|---|---|---|
| **S0 复述** | 把题面读成一个"要造什么"的对象；暴露"没读懂题"这一最常见卡点 | Agent 静默读题后给出 3 句以内的题面复述：给什么 / 要算什么 / 返回什么。**不解释、不给解法** | 读者用一句话说"这题在干嘛"，或指出 Agent 复述里不对的地方（产出型，可错过） | 信号〇：**题面理解度**（复述错 → 直接进 S1 的"卡住"栏） |
| **S1 第一感觉** | 把初学者直觉、常见误区、卡住的位置**显性化并当作素材**；它们是后面要打掉的靶子 | 三栏清单，**只列不评**：①多数人会先试的方向 ②这题最容易踩的坑 ③你大概会卡在哪一步 | 读者勾选 / 补充（"第 2 条我没这个感觉""还有别的坑吗"） | **信号四（新增）：误区分布** → 决定 S2 案例对与 S4 边界的先后顺序 |
| **S2 并置** | 用只差一个参数的案例让差异自己显形（现有第 1–2 段） | 两个案例并置 + 一句"它们哪儿不一样"（不解释） | 读者指出差异点 | 信号一：定位差异 |
| **S3 命名** | 给差异一个可迁移的名字（现有第 3 段） | 命名 + 判据的**口语版**（这一段禁止出现形式化定义） | 读者用自己的话复述"这个判据在说什么" | 信号二：复述粒度 |
| **S4 落地** | 把判据变成可执行的步骤与边界 | 判据 → 算法步骤 → 复杂度。**本阶段允许出现定义、术语、代码** | 读者指出某一步不成立 / 追问边界 | **信号五（新增）：边界质疑** → 校准误差的高价值窗口 |
| **S5 迁移检验** | 检验判据是否真能迁移，而不是"听懂了"（现有第 4–5 段） | 一个只差一个参数的微变体 + 明确交付物（列出 k / 给出次数 / 画出来） | 读者独立推进 | 信号三：独立推进 |
| **S6 复盘** | 把这一题的判断抽象成可迁移的一句话，并接到下一题 | ①这题真正考的判断是＿＿（一句话，能挪到别的题）②下次遇到 X，先问自己 Y ③一道同族下一题 | 读者说"如果换成 XX 我会先想＿＿" | 迁移质量：读者能否自己产出可迁移表述 |

### 3.3 与现有层级 A/B/C、地板条款的映射

| 机制 | 新流程中的位置 | 变化 |
|---|---|---|
| 层级 A（补前置） | S0/S1 天然对 A 层友好；A 层时 S2 换成更小的微过程 | 不变 |
| 层级 B（标准） | S2/S3 完整模板 | 不变 |
| 层级 C（压缩） | S2 只放一个案例对，S3 命名后直接进 S4；S5 保留静默检查点 | 静默检查点从"第五段"移到 S5 |
| 地板条款（完全显性） | S4 全程显性 | 地板层的进入条件不变 |
| 运行模式判定 | **提前到 S0 之前** | 成文模式下 S0/S1/S5 的交互点降级为"邀请作答、不阻塞" |
| 5.1 验收清单 | 移到 S6 之后执行 | 顺序变，但仍是"输出前全检" |

### 3.4 与第三部分（外部技能）的关系

S1 的"第一感觉"和 S0 的"复述题目"并非新发明——它们正是 `vasanthsreeram/Alvarmethod` 的 **Probe 阶段**（`references/process.md`：用分级选择题测出"理解边缘"，并让学习者"用笔记或聊天把自己的推理讲出来，那也是信号"）和 `Sanexxxx777/curated-claude-code` 的 teach 技能里那句 "**FIRST ask them to restate their current understanding in their own words**" 的做法。

**本项目缺的不是这个方法，而是"读者没有回应"时的降级路径**——成文模式下 S0/S1 无法采集信号。降级建议：成文模式下把 S0/S1 写成**读者可勾选的清单**（而非提问），并把 S1 的"常见误区栏"直接作为 S2 案例对的选取依据。

### 3.5 落地成本

- **需要新写的文件**：`docs/stages.md`（七阶段说明），以及配套的第 7 项结构化标注（与 roadmap 2 合并做）。

### 4.1 `bevibing/socrates-skill` —— 苏格拉底式提问

**来源**：`https://raw.githubusercontent.com/bevibing/socrates-skill/main/SKILL.md`

**包含什么**：单文件 SKILL.md（约 100 行）+ README + LICENSE。核心规则一句话写死："**NEVER give a direct answer**… even if the user begs for the answer"。五步工作流：① Understand the subject（**静默**读取目标资源，建立内部理解但不外露）② Assess（开一个口子问题摸底）③ Guide（按 clarifying / probing / connecting / counter / hypothetical 五类问题递进）④ Adapt（依上一次回答简化 / 加深 / 改道）⑤ Confirm（请学习者总结）。另有语言镜像规则、5 条 Anti-Patterns、3 条收尾规则。

**构建哲学**：**把"不答"当成唯一机制，其余全部是围绕它的组织方式**。文件极小（三个文件），价值集中在一条约束上。README 第一行就是 "Never answers. Always asks."

**讲解原则**：问题类型是**上一次回答的函数**，不是固定脚本；方向错时**不纠正**，改用一个能暴露矛盾的追问；对方说"不知道"时降粒度而不是给答案。

**本项目最该借鉴的 3 点**

1. **"方向错了不纠正，用反问暴露矛盾"**。本项目的诊断层拿到负信号后只有两种反应：调整层级（内容侧的间接回应），或者什么都不做。缺少一种**冲着读者那个具体错误发问**的手法。socrates 的做法是："Then how would you explain this case?"——把纠错变成读者自己撞上的矛盾。对应本项目 7.3 信号一的负信号处理。
2. **问题类型梯度应当显式分类，且是递进关系**。socrates 的五类（澄清 → 追问 → 联结 → 反驳 → 假设）里，**counter（"如果反过来会怎样"）和 hypothetical（"如果上线会出什么问题"）是本项目完全没有的提问类型**——本项目只有"哪个变了 / 复述 / 微变体"三种采集点，缺"用反例逼边界"这一路。
3. **Anti-Patterns 清单（越界行为）而非句式禁令**。socrates 禁的是"给出明显等于答案的提示"、"讲完再问懂了吗"、"几次失败后就给答案"——这些是**行为层**的越界。本项目 5.1 禁的是**句式层**的词（`你理解`/`是指`）。行为禁令不产生 AI 味（它约束的是 Agent 的动作），句式禁令却会误伤读者的第二人称（见 1.3）。

### 4.2 `DreambigOu/ELI5` —— 费曼式（受众适配）讲解

**来源**：`https://raw.githubusercontent.com/DreambigOu/ELI5/main/skills/eli5/SKILL.md`

**包含什么**：SKILL.md（约 130 行）+ `eli5-workspace/`（`evals.json`、`run-evals.py`、`eval-results.md`）。**受众矩阵**分四维：年龄（5/10/15/20-30/40+）、学段（小学五年级 → 研究生）、职位（Manager / Engineer / Designer / Director / Colleague / PM）、关系（伴侣 / 父母 / 子女 / 朋友），每类给出"词汇 / 类比 / 语气 / 深度 / 框架"五个旋钮。讲解结构固定为 what → analogy → details → so what。语言校准分"简单受众 / 技术受众 / 商业受众"三档，各给具体写法。3 个完整示例。

**构建哲学**：**"讲给谁听"是第一个要解的变量**，讲解结构是受众的函数而不是内容的函数。更关键的是它**自带评测系统**：每个测试用例写 4 条可验证断言，脚本把每个提示跑两遍（有 skill / 无 skill 的 baseline），用模型自动打分并输出通过率——README 报告当前 **83.3% vs 41.6%（+41.7%）**，且指出最大增益在"面向非技术受众时的框定方式"。

**讲解原则**：先讲目的再讲机制（"Nobody cares about syntax until they know why it exists"）；对非技术受众允许"80% 准确换全场听懂"；永远不居高临下。

**本项目最该借鉴的 3 点**

1. **把"受众"提升为与"层级"正交的第一变量**。本项目的 A/B/C 只回答"概念前置够不够"，不回答"讲给谁听"。同一条断点判据，讲给算法竞赛选手和讲给考研复试的人，用词、结构、例子完全不同；而**受众是读者自己一句话就能说明的**（`--audience 竞赛选手`），却比推断层级便宜得多。
2. **把"有效"写成可自动判的断言**。本项目 5.1 只验**形式合规**（词频、位置、句式），完全没有验"教学是否有效"；ELI5 的做法是把"该不该有儿童类比""语气是否不油腻"写成 4 条断言，用 baseline 对照量化增益。**本项目完全可以用同一套路给课文做评测**：例如"第 2 段并置案例的两个答案必须不同"、"第 3 段的命名必须能被第 5 段复用"、"全文不得出现第二人称评价型句式"。
3. **"so what"收尾**。本项目第五段是"回扣"——回扣的是判据本身，没有回扣**"这题为什么值得学/用在哪"**。ELI5 把"so what"作为固定收尾位，代价一行，收益是让知识挂到读者已有的价值体系上。

### 4.3 `vasanthsreeram/Alvarmethod` —— 知识图谱式一对一教学

**来源**：`https://raw.githubusercontent.com/vasanthsreeram/Alvarmethod/main/skills/teach/SKILL.md` + `references/philosophy.md` + `references/process.md`

**包含什么**：一个技能包（5 个技能：`teach` / `probe` / `learn-profile` / `learn-visual` / `learn-verify`）+ 4 份 references + `assets/LEARNER.md` + `install.sh`。方法四段：**Probe → Plan（mermaid 依赖图）→ Teach（一次一个推理步）→ Lock-in quiz**。硬规则：挣扎留在材料里、Agent 承担物流；不重讲已知；一个 turn 只推进一步；**先给 mermaid 图再教**；永不一次性倾倒；信任要工程化（不确定就核实再教）。

**学习者档案持久化**：`.alvar/LEARNER.md`（学习者画像）+ `.alvar/maps/<topic>.md`（理解地图）+ `.alvar/sessions/<date>-<topic>.md`（会话记录）+ `.alvar/visuals/`。

**构建哲学**（`references/philosophy.md`）：**"one teacher, one mind"**。论证是三段：面向大众的教材对任何单个人都不是最优（教学应停在**理解边缘**）；一人从多个来源学习则要付出切换与**信任对冲**成本；解法是"一个接口、多个来源"，而信任可以被**工程化**（核实与事实核查让学习者不必再对冲）。两条原则：优化教学、优化心智资源分配。

**讲解原则**：Probe 用**分级选择题**（含"我不知道"）从宽到窄**二分**找理解边缘，边缘只有在"能答对的地板"与"答错的天花板"同时存在时才算定位到；Plan 画依赖 DAG 并在教学前展示（"图强迫你把推理走完"）；Teach 每个节点后立刻 quiz，**锁入才前进**，失败就留在原地或插入前置节点。

**本项目最该借鉴的 3 点**

1. **"先给计划图再教学"**。本项目是"案例先行"，但读者**看不到这篇课会经过哪些概念、依赖关系是什么**；Alvarmethod 强制在教学前展示 mermaid DAG 并问"要不要改图"。收益有三：读者有路线感；图本身暴露"这个课其实缺了前置"；图是天然的复盘材料。对本项目的具体形态：一个"模块 × 概念依赖"的图（本课用到 唯一目标 / 断点 / 目标块对齐 三个概念），比五段式更早暴露缺口。
2. **跨会话的学习者档案**。本项目每次都冷启动 B 层、靠单次对话内的信号推断层级，**同一用户讲第二道题时从零开始**。`.alvar/LEARNER.md` + `maps/` + `sessions/` 三件套是一个可以直接抄的形态：本项目可以落 `.workbuddy/learner/<user>.md`（已知概念/已掌握模块/常见卡点）+ `maps/<topic>.md`（每题的依赖图）。这同时能缓解第二部分说的"每次重新推断"的耗时。
3. **"锁入"作为前进的硬条件 + quiz 走原生 picker**。本项目把验证降级成"第五段末尾一个微变体"，且**不要求读者作答就结束**；Alvarmethod 是"每个节点后立刻 quiz，答不上来就不许前进"，并且明确要求用 harness 的原生选择题组件（"Never A/B/C/D in chat"），因为聊天里贴选项会被读者当成装饰。

### 4.4 `mohi-devhub/antivibe` —— 代码学习与架构审计

**来源**：`https://raw.githubusercontent.com/mohi-devhub/antivibe/main/SKILL.md` + `agents/auditor.md`

**包含什么**：SKILL.md + `agents/auditor.md`（senior 模式路由）+ `templates/deep-dive.md` + `scripts/`（capture-phase / analyze-code / find-resources / generate-deep-dive 四个 shell 脚本）+ `hooks/hooks.json`（`SubagentStop` / `Stop` 自动触发）。两个模式：**Deep Dive**（学习）与 **Audit**（审计）。两种输出模式：`compact`（默认，只 what+why，**最多 5 个文件**，控 token 成本）与 `full`（逐行走查 + 前置 + 资源 + 下一步）。三级深度：junior / mid / senior。**`known_concepts` 跳过列表**——用户自己维护"我已经会的概念"清单，命中则只给一句话带过。**Prerequisites 映射**——每个概念标注"要懂它先得掌握什么"。

**构建哲学**：**"理解"与"接受"必须分开**——AI 写代码、人复制粘贴、谁都没学会；所以这个技能的存在理由就是把"为什么这么写"讲出来。而且它**不假设代码是 AI 写的**：任何代码（新的、遗留的、生成的）都能审计，"你不需要 git 历史"。子代理分工：explainer 出学习内容，auditor 出权衡笔记。

**讲解原则**（`agents/auditor.md` 写得很硬）：**Why over what**；每个概念给 What / Why / When / Alternatives / Prerequisites 五项；先讲目的再讲机制；审计模式"每一行输出都必须给出读者自己看不到的东西"；"没有真东西可说的段落就写 'Nothing notable.' 并继续"；**总长上限 500 词，"简洁是一种特性"**。

**本项目最该借鉴的 3 点**

1. **`known_concepts` 跳过列表：把"用户已经会什么"外置成显式配置**。这是本项目最大的缺口。层级 A/B/C 每次都要**靠弱信号推断**"读者缺不缺前置"，推断成本高、还可能错；而"我知道哪些概念了"是用户一句话就能给出的确定信息。给本项目加一份 `learner.md`（或 `.workbuddy/learner/`），命中即跳过相关铺垫——**同时解决第一部分的部分耗时**（第二部分的"每次重新推断"）。antivibe 用 `known_concepts` + `default_level` 两个 YAML 块实现，本项目可以用同样形态。
2. **`compact` / `full` 双模式 + 明确的体量上限**。本项目每篇课文只有一种密度。真实需求是分层的："这题我只想知道思路"（compact：判据 + 复杂度，不要代码、不要对拍）vs "我要能提交"（full：全部）。antivibe 的 compact 模式**只做 what+why、不做逐行、不给资源、最多 5 个文件**——这是一个明确的 token 预算约束，本项目可以在 5.1 之外加"篇级预算"（汉字上限 + 段数上限 + 可选段清单）。
3. **"没有真东西可说的段落就写 'Nothing notable.' 并继续"**。本项目 5.1 鼓励**段数齐全**（五段式模板固定五个槽位），这在内容不足时会逼出**凑数的段落**——这正是 AI 味的来源之一（空洞概括、机械排比）。antivibe 的做法是**允许一个槽位为空，并给出明确的占位符**。对应到本项目：`check_lesson.py` 第 10 项"B 层配置：模板五段齐全"应改为"**五段要么有实质内容，要么显式标注为不适用**"——用占位符换掉填充。

### 4.5 横向对照

| 维度 | socrates-skill | ELI5 | Alvarmethod | antivibe | **本项目** |
|---|---|---|---|---|---|
| 核心机制 | 只问不答 | 受众适配 | 探边→依赖图→单步教学→锁入 | 学习/审计双模式 | 并置案例→参数微调→命名 |
| 文件量 | 极小（1 个 SKILL.md） | 中（+ 评测工作区） | 大（5 技能 + 4 references + 安装器） | 大（+ 子代理 + 脚本 + hooks） | **大（SKILL.md 单文件 507 行 / 15.8k tok）** |
| 自带评测 | ✗ | **✓（断言 + baseline + 通过率）** | ✗ | ✗ | **✗（5.1 只验形式）** |
| 持久化学习者状态 | ✗ | ✗ | **✓（LEARNER/maps/sessions）** | 部分（跳过列表） | **✗** |
| 人工交互点密度 | 高（每答必问） | 低（一次性） | **高（每节点 quiz）** | 低（一次性产出文件） | **低（成文模式仅末尾一个微变体）** |
| 首问是什么 | "你认为 X 是什么" | "讲给谁听"（隐含在 prompt） | "先探你的理解边缘" | "分析哪个文件" | **直接给案例（无题面复述）** |
| 唯一大优势 | 逼出读者自己的表述 | 把"讲给谁"工程化 | 学习者状态持久化 + 图先行 | known_concepts + 体量预算 | **形式化验收清单（别的都没有）** |
| 唯一大短板 | 读者急了就卡死 | 无教学闭环验证 | 重、装得多 | 无学习效果验证 | **只验形式不验效果；成文模式无交互** |

**结论性观察**：四个技能里，**只有本项目有"可机器校验的验收清单"**，但**没有一个有"教学效果的评测"**。ELI5 的做法（断言 + baseline + 通过率）是唯一一条已经被验证有效的路径，而它恰恰是本项目 5.1 想做但止步于"形式合规"的那件事。
