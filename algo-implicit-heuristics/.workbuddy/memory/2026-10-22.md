## algo-implicit-heuristics 上架 WorkBuddy 云端个人技能库

**目标**：让技能在云端（Web 端 / 云端任务）也能用，而不只是客户端本地。

**关键事实（实测自 WorkBuddy 客户端 asar 与官方文档）**
- 客户端 `~/.workbuddy/skills/` 是**本地个人库**；官方明确「Web 端和客户端的个人 Skill 库互不相通」，云上任务只能选到**云上个人库**里的 Skill。所以本地装了 ≠ 云端能用。
- 云端上传接口：`POST /v2/user-asset/custom-skills`，multipart 表单 `file`(zip) + `name` + `title` + `description` + `version`。
- 查询：`GET /v2/user-asset/custom-skills/{skillUid}`（status 轮询，ready/invalid/failed 为终态）；
  列表：`GET /v2/user-asset/skill/get-list?source=custom`。
- **同名同版本会被拒绝**：`17416:skill "xxx" is already at version x.y.z` → 每次发布必须递增版本。
- 服务端会解析 SKILL.md frontmatter，YAML 非法或缺 name/description → 判 invalid。

**做法（已固化为 `scripts/publish_skill_to_cloud.py`）**
1. 打包 `skills/<name>/` 为 zip（顶层目录名 = 技能名）。
2. 通过客户端 WBIPC 通道发请求，**不自己拿 token**：
   - 模块：`{WorkBuddy}/resources/app.asar.unpacked/resources/plugins/workbuddy-builtin/skills/library/workbuddy_ipc/__init__.py`
   - `connect(client_id=..., client_kind="skill")` → `get_pipe("wb.request")` → `invoke("http.fetch", {...})`
   - 宿主自动注入 `Authorization` / `x-user-id` 等 header，请求体走 `body_b64`（仅 JSON body）。
   - **multipart 需手工拼 boundary**，content-type 形如 `multipart/form-data; boundary=----WBSkill<hex>`。
   - 路径必须相对且以 `/` 开头，query 走 `query` 字典（不能带 `?`），header 只允许 `content-type` / `accept`。
3. 轮询到 `ready` 再校验列表中出现该项。
